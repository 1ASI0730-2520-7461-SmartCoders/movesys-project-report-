# 📘 Backlog Unificado – Nuevas User Stories MoveSys

| **Epic / Story ID** | **Título** | **Descripción** | **Criterios de Aceptación** | **Relacionado con (Epic ID)** |
|----------------------|------------|------------------|------------------------------|-------------------------------|
| **EP06** | Panel de control operativo | Como gestor necesito un panel principal que consolide la información de entregas, flota, mantenimiento y desempeño para monitorear la operación diaria. |  |  |
| US-26 | Monitorear indicadores del día | Como gestor quiero visualizar los valores de entregas completadas, unidades activas y rendimiento diario en el dashboard. | **Escenario 01: Consulta de indicadores**<br>Given que hay datos operativos del día, When el gestor accede al dashboard, Then el sistema presenta los valores actuales.<br>**Escenario 02: Cálculo de eficiencia**<br>Given que hay registros de entregas finalizadas, When se muestran los indicadores, Then el sistema calcula el porcentaje de eficiencia.<br>**Escenario 03: Alerta de bajo desempeño**<br>Given que el rendimiento cae por debajo del umbral definido, When se actualiza el panel, Then el sistema genera una notificación de alerta. | **EP06** |
| **EP07** | Control de consumo de combustible | Como gestor necesito registrar y analizar el consumo de combustible de las unidades para optimizar los costos operativos. |  |  |
| US-27 | Registrar consumo por unidad | Como gestor quiero registrar los datos de recarga de combustible por vehículo para llevar control del gasto. | **Escenario 01: Registro de recarga**<br>Given que se realiza una recarga de combustible, When el gestor ingresa la cantidad y costo, Then el sistema almacena el registro con fecha y hora.<br>**Escenario 02: Cálculo de rendimiento**<br>Given que existen registros de kilometraje y consumo, When se actualiza la información, Then el sistema calcula el rendimiento de combustible por km.<br>**Escenario 03: Validación de datos**<br>Given que se ingresan valores inconsistentes, When se guarda el registro, Then el sistema notifica el error y solicita corrección. | **EP07** |
| US-28 | Generar reporte de consumo mensual | Como gestor quiero obtener un informe consolidado del consumo mensual por vehículo y ruta. | **Escenario 01: Generación de informe**<br>Given que existen registros de consumo, When el gestor solicita un reporte mensual, Then el sistema agrupa los datos por vehículo y periodo.<br>**Escenario 02: Comparativa de eficiencia**<br>Given que hay unidades con bajo rendimiento, When se genera el reporte, Then el sistema marca las diferencias de eficiencia entre vehículos.<br>**Escenario 03: Exportación de datos**<br>Given que el reporte ha sido generado, When el gestor solicita exportarlo, Then el sistema lo genera en formato descargable. | **EP07** |
| **EP08** | Gestión de usuarios y roles | Como administrador deseo gestionar los usuarios del sistema, sus roles y permisos para garantizar seguridad y control de acceso. |  |  |
| US-29 | Asignar roles y permisos | Como administrador quiero definir qué módulos puede acceder cada usuario según su rol. | **Escenario 01: Asignación de rol**<br>Given que el administrador registra un usuario, When define su rol, Then el sistema aplica automáticamente los permisos asociados.<br>**Escenario 02: Restricción de acceso**<br>Given que un usuario intenta acceder a un módulo no autorizado, When ejecuta la acción, Then el sistema deniega el acceso y muestra una notificación.<br>**Escenario 03: Actualización de roles**<br>Given que se necesita modificar un rol, When el administrador actualiza los permisos, Then el cambio se aplica inmediatamente. | **EP08** |
| **EP09** | Reportes inteligentes | Como gestor deseo generar reportes personalizados que muestren métricas de rendimiento y operación logística. |  |  |
| US-30 | Crear reportes personalizados | Como gestor quiero seleccionar métricas específicas para generar un reporte adaptado a mis necesidades. | **Escenario 01: Selección de métricas**<br>Given que existen diferentes indicadores, When el gestor elige los que desea incluir, Then el sistema genera un reporte con esas métricas.<br>**Escenario 02: Guardado de plantillas**<br>Given que el gestor crea un formato recurrente, When lo guarda, Then el sistema permite reutilizarlo.<br>**Escenario 03: Generación automática**<br>Given que se ha configurado un reporte periódico, When llega la fecha establecida, Then el sistema lo genera automáticamente. | **EP09** |
| **EP-LP** | Sitio web estático (Landing Page) | Como visitante quiero conocer los servicios, beneficios y precios de la plataforma para decidir si contratarla. |  |  |
| US-31 | Explorar beneficios de la plataforma | Como visitante deseo visualizar los beneficios clave que ofrece MoveSys para empresas de transporte. | **Escenario 01: Consulta de beneficios**<br>Given que el visitante accede al sitio web, When selecciona la sección “Beneficios”, Then el sistema muestra la información correspondiente.<br>**Escenario 02: Enlace a casos de éxito**<br>Given que el visitante desea más información, When selecciona “Ver casos reales”, Then el sistema muestra ejemplos aplicados de éxito. | **EP-LP** |
| US-32 | Contactar soporte comercial | Como visitante quiero enviar un mensaje de contacto para recibir atención personalizada. | **Escenario 01: Envío exitoso**<br>Given que el visitante completa el formulario de contacto, When envía la solicitud, Then el sistema registra el mensaje y muestra una confirmación.<br>**Escenario 02: Validación de datos**<br>Given que el visitante ingresa datos incompletos, When intenta enviar la solicitud, Then el sistema solicita completar los campos requeridos.<br>**Escenario 03: Respuesta automática**<br>Given que el mensaje es recibido, When se genera el registro, Then el sistema envía una confirmación automática al correo indicado. | **EP-LP** |
| **EP-API** | API RESTful | Como desarrollador necesito acceder a los servicios a través de endpoints para integrarlos con otras aplicaciones. |  |  |
| TS-06 | Registro de consumo vía API | Como desarrollador quiero registrar eventos de consumo de combustible mediante endpoints para integrarlos con aplicaciones externas. | **Escenario 01: Registro válido**<br>Given que se envía una solicitud POST con datos correctos, When la API procesa la petición, Then responde con código 201 y confirmación de registro.<br>**Escenario 02: Validación de errores**<br>Given que los datos enviados están incompletos, When la API procesa la solicitud, Then retorna error 400 con descripción del campo faltante.<br>**Escenario 03: Autenticación requerida**<br>Given que no se incluye token de autenticación, When se realiza la solicitud, Then la API responde con error 401. | **EP-API** |
